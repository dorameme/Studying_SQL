# JOIN 조건에서 OR을 사용하지 않는 이유

## 1. 개요

JOIN 조건에 OR을 포함하면 옵티마이저가 인덱스를 효과적으로 활용하지 못하고 성능이 급격히 저하되는 문제가 발생한다.


## 2. JOIN 조건에서 OR이 문제가 되는 이유

### 2.1 인덱스 사용 불가 가능성이 높아진다

JOIN은 일반적으로 두 테이블을 연결하면서 인덱스를 기반으로 빠르게 매칭한다. 하지만 OR 조건이 들어가면 조건 분기가 발생하여 단일 인덱스 경로로 탐색하기 어려워진다. 그 결과 옵티마이저는 인덱스를 포기하고 풀 스캔을 선택하는 경우가 많다.

### 2.2 조인 순서와 실행 계획이 불안정해진다

OR 조건이 있으면 옵티마이저가 기준 컬럼을 하나로 고정할 수 없다. 이로 인해 조인 순서가 단순화되지 못하고, 해시 조인이나 풀 스캔 기반의 조인을 선택하기 쉬워진다.

### 2.3 조인 조건의 카디널리티 추정이 어렵다

OR은 두 조건을 합산하는 방식으로 처리되므로 중복 고려가 필요하고 실제 행 수 추정이 어려워진다. 이 추정 오류는 곧 실행 계획의 비효율로 이어진다.

---

## 3. 예시

### 비효율적 예시 (JOIN + OR)

```sql\SELECT *
FROM A
JOIN B ON A.id = B.id OR A.sub_id = B.sub_id;
```

이 예시는 두 조건 중 하나만 맞아도 JOIN이 이루어진다. 인덱스 탐색 경로가 두 개로 분리되므로 옵티마이저는 인덱스 기반 NL 조인을 사용하지 못하고 풀 스캔 또는 해시 조인을 선택할 가능성이 매우 높다.

### 개선된 예시 (UNION ALL 사용)

```sql
SELECT *
FROM A
JOIN B ON A.id = B.id
UNION ALL
SELECT *
FROM A
JOIN B ON A.sub_id = B.sub_id;
```

두 조건을 강제로 분리하여 각각 독립적인 인덱스 사용이 가능해진다. 옵티마이저는 두 조인을 각각 최적화할 수 있다.

---

## 4. 비교 표

| 구분        | JOIN + OR | JOIN 분리(UNION 방식) |
| --------- | --------- | ----------------- |
| 인덱스 사용    | 어려움       | 매우 유리함            |
| 실행 계획 안정성 | 낮음        | 높음                |
| 카디널리티 추정  | 어렵다       | 정확도가 높다           |
| NL 조인 활용  | 거의 불가     | 가능                |
| 성능        | 느린 경우가 많다 | 일반적으로 빠르다         |

---

## 5. 결론

JOIN 조건에 OR을 넣는 것은 성능 저하를 유발하기 때문에 피하는 것이 좋다. 동일한 효과가 필요하다면 조건을 분리하여 UNION ALL로 처리하는 것이 인덱스 활용 면에서 훨씬 효율적이다.
